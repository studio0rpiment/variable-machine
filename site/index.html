Variable Machine

A localhost instrument for changing small language models on an Apple Silicon Mac: try models, change them with words, collect examples, train, blend, compare and share. Every click shows the real command it runs in a terminal at the bottom of the page.

Install v0.2.9: open Terminal (cmd-space, type Terminal, press Return), paste this line and press Return. Install Ollama and Node first: what you need.

curl -fsSL https://variablemachine.orpiment.studio/install.sh | bash
Download v0.2.9 (zip) The code on GitHub What changed in each release

Free and open source (MIT). It runs entirely on your own Mac: nothing you type or make is sent anywhere.

Start here

You need: a Mac with Apple Silicon (M1 or later) and 16GB of memory or more, macOS 14 or later, and about 10GB of free disk.

  1. Install two things (once)
    • Ollama, which runs the models: download it from ollama.com and install it. You don't need to open it.
    • Node 22 or newer, which runs the app: download the LTS installer from nodejs.org and open it.
  2. Paste one line into Terminal

    Open Terminal (press cmd-space, type Terminal, press Return), paste this line, and press Return:

    curl -fsSL https://variablemachine.orpiment.studio/install.sh | bash

    It downloads the newest release into a variable-machine folder in your home folder, makes a Variable Machine app in Applications, and opens it. The app opens a Terminal window, checks your Mac, and tells you plainly if Ollama or Node is missing. The first time it also installs uv (which runs training) and what the app uses, which takes a few minutes. Then it starts Ollama and the app and opens http://localhost:4817 in your browser. Every command it runs is shown with ▸ in front. Read the install script.

    Why not the zip? macOS won't open a script downloaded in a browser unless Apple has signed it. The line above downloads with curl, which macOS doesn't block, and makes the app on your own Mac.

    Next time, open Variable Machine like any other app: cmd-space, type Variable Machine. You can drag it to the Dock. To stop it, close its Terminal window. To update it, paste the same line again: your workspace stays as it is.

    Working on the code? Clone it and use npm run dev, which rebuilds on every save:

    git clone https://github.com/studio0rpiment/variable-machine
  3. Your first ten minutes
    1. Start shows a map of every tab and what flows between them. Click a box to open it; about has the same in words.
    2. Models: press ollama pull smollm2:360m on its card (about 700MB).
    3. Modelfile: choose a preset, press make variant, and ask the original and your variant the same question.
    4. Data → Train: add one of the datasets that come with the app, open Train with it, and train. When it finishes, the next step exports your model and opens Chat with it.

If something isn't right: npm run doctor checks Ollama, uv, Python and memory and says what to fix. In the app, hover over any tab name or control for a flag that explains it.

Disk: smollm2:360m is 725MB and qwen3:4b 2.5GB. The first training run downloads its base model (about 700MB for SmolLM2-360M, 3.4GB for the 1.7B).

Three ways to change a model

A language model is a large file of numbers learned from text. You can't edit those numbers by hand, but you can change what the model does:

words
Modelfile: standing instructions, a temperature and an example placed in front of the model. No training: the same numbers, reading a note before every question.
examples
Train: show it questions with the answers you want until it answers like them. Training leaves the model untouched and learns an adapter, a small set of changes.
taste
Prefer: show it pairs of answers, one marked better, and it leans toward the kind you chose.
blend
Merge: mix two adapters into a third, with a slider for how much of each.

Then Adapters turns what you made into a model of your own, Chat puts it next to the original, and Share zips it, with the record of where its data came from and its license.

Four worked examples, animated: one model made each way (a studio critic by words, colour names to hex codes by examples, haiku that keep 5-7-5 by taste, and a blend of the last two), drawn step by step from the real records.

The tabs

start
A clickable map of every tab, read left to right: what you bring, preparing it, how a model learns, making it a model, using it.
1 models
Four very different starters and a library to download from, each with what it was built for and its license, and SmolVLM, a model that sees.
2 modelfile
Change a model with words, from twelve presets or your own, and hear the original and your variant answer the same question.
3 data
Datasets that come with the app, any dataset on Hugging Face by name, your own file, or a table from DC Open Data or data.gov turned into questions and answers; or photos with what they show, for a model that sees. For a table, see what's in each column and what it means in a question, then make a training set with one button: questions from the table's own values, each with the query that answers it, so the model learns to look things up rather than remember them. Every dataset keeps its source and license.
4 train
Imitate: LoRA training with the loss explained in plain words as it runs, and a warning before settings that won't work. A picture dataset trains SmolVLM.
4 prefer
Lean toward the better answer (DPO), from pairs you chose in Chat.
4 merge
Blend two adapters.
5 adapters
Export what you trained into a model, and try it on questions it never saw.
chat
Up to four models side by side, one question, and a picture for the models that see. Ask the table: a model trained on a table writes a query, and the answer is counted from the table, shown with the query, the rows behind it and the same query in SQL. When the table can't answer, it says so rather than guess.
share
Zip anything you made, and unzip what someone sent you. A model that asks a table becomes a package for another project: the model, the table, a one-page demo, and ask.js for a web page, Node, Python, or TouchDesigner and Max over OSC. On another computer it needs only Ollama.
image segmentation
Ready-made image tools, used as they are, that find the regions of a picture: cut something out, the distance between blobs, select a blob. They run in the page.
speech
A model that speaks your text aloud, and one that writes down what it hears in your recording, in 52 languages and dialects.
gesture
Gesture recognition: points on your hands (one or two) or body from the camera; tap to record a few gestures of your own, train a model that names them in seconds, and send what it sees as OSC to TouchDesigner, Max or Pure Data.

For teaching

The class project: in groups of three, students choose one of four demos (public data, gallery, gesture, tangible), make it work, then retrain it on data of their own for a larger project. They hand in the model they made, with a model card that says what they did, why, and what the larger project is.

Removing everything

For anyone who wants it all gone again (the app, everything made with it, the models, Ollama, uv, and Node if it came from nodejs.org): in Terminal, in the variable-machine folder,

bash scripts/remove-everything.sh

It shows what each step removes and its size, and asks before each one. Most of it goes to the Trash, so empty the Trash to delete it for good. --dry-run only shows what it would remove.
